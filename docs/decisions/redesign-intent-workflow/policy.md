## 方針

- **P1. 先に今の形を棚卸しする。** 置き場ごとに、誰が書き、どのスキルと人が読み、どこまで信じられているかを表にする。あわせて、スキルごとに、いつ呼ばれるか・何を持つか・隣と重なるところ・渡す先を表にする。表は、読んだ commit の時点の記録として書く。根拠：持ち主 2026-11-13（手順1。スキルの関係の表は PR #10 の確認）。
- **P2. 困りごとを読み手ごとに分け、出典を付ける。** 読み手は人とエージェントに分ける。出典が無いものは「推測」と書く（S1）。根拠：持ち主 2026-11-13（手順2）。
- **P3. 参考は agent-taxonomy から引き、上流の版で確かめる。** 同じ分野の JOB の比較の表から3〜5件を選び、ほかの作者のスキルの分け方と description の書き方を見る。手元の写しで判断しない（S2）。根拠：持ち主 2026-11-13（手順3。agent-taxonomy から引くことは PR #10 の確認）。
- **P4. 案ごとに、効果・維持コスト・抜け道を並べる。** 効果は、どの困りごとが消えるかで書く。変えてはいけないものを先に書く。根拠：持ち主 2026-11-13（手順4）。
- **P5. 決めたいことは、推奨付きで選べる形で聞く。** 推奨で決めてよいものは決めて並べる。人が OK した項目と、推奨のまま進めた項目を分けて書く。根拠：持ち主 2026-11-13（手順5）、create-intent-skill/SKILL.md の手順1の4。
- **P6. 設計書はチーム向けに書く。** 根拠には、読み手が確かめられるものを使う（S3）。決定の重さ（戻すのが高くつく決定か、試しに決めたことか）を分けて書く。根拠：持ち主 2026-11-13（手順6）。決定の重さは、持ち主が OK（2026-11-13）。
- **P7. 移行は、渡せる大きさの PR に分けて渡す。** 各 PR に、渡し先（create-intent-skill か improve-intent-skill）と前後の依存を付ける。このスキルでは、対象のスキルの本文を直さない。improve-intent-skill に渡す変更は、設計書で人が決めたものとして渡す。根拠：持ち主 2026-11-13（手順7、improve と分ける理由の2つ目）。「本文を直さない」は、持ち主が OK（2026-11-13）。2文目は下書き（改善の入口が分担の相談を止めるので、設計書から渡された変更が入口と数えた失敗の縛りで止まらないようにする）。
- **P8. 1つのスキルの相談でも、論点が隣との分担なら受ける。** 論点は、いつ呼ばれるか（description）、何を持つか、どこで渡すか。1つのスキルの中では決められないため。根拠：持ち主 2026-11-13（PR #10 の確認。例：PR を作るスキルの description を、文章を書くスキルとの関係を見て直す相談）。

- スキルを1つ新しく作ること。それは create-intent-skill の仕事。根拠：create-intent-skill/SKILL.md の冒頭（出力はスキル1つ分の3つのファイル）。持ち主が OK（2026-11-13）。
- 移行の PR を、このスキルの中で実装すること。渡し先のスキルの手順で実装する（P7）。持ち主が OK（2026-11-13）。
- 評価のループ（スキルあり・なしで並べて実行し、採点する仕組み）を組むこと。根拠：create-intent-skill/policy.md の非目標。持ち主が OK（2026-11-13）。
- 参照先の文を訳したり、並べ替えたりして持ち込むこと。根拠：create-intent-skill/policy.md の非目標。

方針どうしがぶつかったら、上から先に譲る。持ち主が OK（2026-11-13）。形は create-intent-skill/policy.md と improve-intent-skill/policy.md の譲る順に合わせた。
