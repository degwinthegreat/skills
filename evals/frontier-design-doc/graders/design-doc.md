出典：2026-11-14、前の版にこのプロンプトを渡すと、仕様書の JSON・表・チケットの雛形だけを返した。流れの成功の定義、範囲の外、未決の問いを書いた設計書が無かった。

次をすべて満たせば合格。

- 仕様書の JSON とは別に、設計書（文章）の全文が返答にある。
- 設計書に、なぜこの流れにするか（プロンプトの「流れを変えたい理由」に当たること）が書いてある。
- 設計書に、範囲の外（この流れでやらないこと）が書いてある。
- 設計書に、はい・いいえで判定できる成功の定義が 1 つ以上ある。「スムーズに回る」「質が上がる」のような、判定できない言葉だけなら不合格。
- 設計書に未決の問いがあり、チームが決めていない目標の数値（デプロイの頻度など）がそこに置かれている。

判定に関係しないこと：節の名前と順番、設計書の長さ、表やチケットの雛形の中身、HTML を書こうとしたか。
