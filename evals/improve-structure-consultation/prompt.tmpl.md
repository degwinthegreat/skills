/{{SKILL_INTENT}} うちのチームでは、設計の決定を ADR に書いている。PR を書くスキルと、設計を相談するスキルの2つが、どちらも ADR を読む。困っているのは、古い ADR まで今の仕様として信じられてしまうこと。エージェントが、もう変わった決定に沿って作業することがある。どれか1回の失敗というより、ADR の置き場と読まれ方そのものに違和感がある。どうしたらいい？

リポジトリは手元に無いので、次の材料だけを使ってください（どれも、そのまま写したもの）。

`docs/adr/` にある ADR（3件）：

```markdown
# ADR-003 API の認証はセッションで行う
状態：採用（2025-04）
決定：API の認証は、サーバーのセッションで行う。
```

```markdown
# ADR-011 API の認証をトークンに切り替える
状態：採用（2026-02）
決定：API の認証は、署名付きのトークンで行う。セッションは管理画面だけに残す。
```

```markdown
# ADR-012 ログは JSON で出す
状態：採用（2026-03）
決定：アプリのログは1行1件の JSON で出す。
```

ADR-003 の本文には、ADR-011 で置き換えられたことが書かれていない。

スキルの説明（2件）：

- `pr-writer`（`.claude/skills/pr-writer/SKILL.md`）：PR の本文を書く。手順の1つ目に「`docs/adr/` の ADR をすべて読み、本文が決定に沿っているかを確かめる」とある。
- `design-consult`（`.claude/skills/design-consult/SKILL.md`）：設計の相談に答える。「答える前に `docs/adr/` を読み、決まっていることには従う」とある。新しい決定が出たら、ADR の下書きを書く。

チームの外の人も `docs/adr/` の ADR に URL でリンクしている。
