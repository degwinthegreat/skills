/{{SKILL_SPEC}} SPEC.md の §4 に、回答の評価で毎回同じ3つの問いを使って、前の版と比べる仕組みを足したい。

リポジトリの AGENTS.md（抜粋）：

```markdown
- 設計の記録は docs/design/<日付>-<短い名前>.md に置く
- SPEC.md には全体の約束だけを書く。細部は docs/design/ から指す
```

SPEC.md（全 1,800 行。目次と §4 だけを載せる）：

```markdown
# 架空の社内向け問い合わせボット SPEC

## 目次
- §1 原則（N1〜N9。N2：測った結果だけを残し、推測の数字を書かない）
- §2 用語
- §3 仕組み（P1〜P9。P7：評価は夜のバッチで走る）
- §4 回答の評価
- §5 運用

## §4 回答の評価
- 週に一度、回答の質を測る。N2 に従う。
- 評価の流れは P7 のとおり。
```

リポジトリに用語集と feature map は無い。

人しか知らないことは、先に答えておく。

- 目的：ボットを変えたときに、回答が前より悪くなっても気づけない。それを無くしたい。
- 成功の定義：ボットを変えるたびに同じ3つの問いで測り、前の版より悪ければ分かる。
- 変えてはいけないもの：§1 の N2。

3つの問いの中身と合格の基準は、持ち主の手元のノートにあり、リポジトリには入れない。

この作業場所には書き込めないので、仕様書の全文と、SPEC.md に入れる変更を返答に出して。
