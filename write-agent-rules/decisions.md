# write-agent-rules の決定の記録

write-agent-rules を、create-intent-skill の手順で作ったときの記録（2026-11-13〜14）。はじめは write-context-doc の名前で、規約と仕様の両方を対象に作った。2026-11-14 に持ち主が、規約だけに絞って名前を変えると決めた（5節）。0〜4節のうち、仕様に関わる記述は、作ったときの記録として残している。理由は [policy.md](policy.md) の項目番号（P1〜P4）と、[共有の方針](https://github.com/degwinthegreat/skills/blob/main/create-intent-skill/shared-policy.md)の S1〜S3 で書く。要旨は、そのルールが write-agent-rules で何を決めるかを、こちらの言葉で書いたもので、原文の訳ではない。

## 0. 要求を疑った結果（create-intent-skill の手順1の2）

既存のもので済むかを先に確かめた。

- 規約の文書を書くスキル（下の参照先の GA と PE）は、割れている論点の片側に決めている。たとえば GA は理由を書かない側、上限を 60〜100 行に決める側。チームに決めさせる形を持たない。
- 文書の書き方の参照（MW）は一般論で、規約を差し戻せる形のチェックとしては持たない。
- 文書の種類を表で持ち、あとから種類を足せるものは無かった。
- メモリの1行や lint は、チームの決めごとを聞く手順を持たないので代わりにならない。ただし、長さの上限（C2）のように機械で判定できるものは、チームのリポジトリで検査にする候補として扱う（C10）。

そこで、新しいスキルを作る。スキルの SKILL.md を書くことは、create-intent-skill と improve-intent-skill の仕事なので、対象にしない（policy.md の非目標）。

## 3. 形（/principles の判断の手順を上から当てた結果）

1. 機械で判定できるもの：C2（長さの上限）と、手順2の2（パスとコマンドの実在）。どちらも、使うチームのリポジトリで検査にするものなので、このスキルには作らない。C2 と C10 で、検査にする候補として書かせる。このスキル自身の検査は、同じ抜けが2回起きてから考える（create-intent-skill の P3、P4）。
2. 分岐の条件（入口で対象外の種類を止める、チームの決めごとが無い論点を聞く、見直しで消す直しを提案にとどめる）は、SKILL.md の本文に置いた。
3. 毎回要る事実は無い。常に読み込まれるメモリには何も追加しない。
4. 文書の種類の表と論点の表は、どの実行でも読むので本文に置いた（P3）。手元の道具だけで使う手順は無いので、local.md は持たない。
5. 共有するもの：共有の方針 S1〜S3 は、GitHub の URL で指す。SKILL.md の本文は、ほかのスキルのファイルを読まない。そのため、1つだけで入れても動く（README）。
6. サブエージェントは使わない。
7. 適用されたかは、返答の4つ（とくに、チームが決めた論点と推奨のまま進めた論点、差し戻したチェックの件数）で見える。

起動のされ方：手動でだけ（`disable-model-invocation: true`）。このリポジトリのほかのスキルと同じく、人が名前で呼ぶ。持ち主が OK（2026-11-14）。規約のファイルを直すたびにモデルが呼ぶ形にする案もあるが、description が毎回読まれる負担と、意図しない場面での起動を避けた。

SKILL.md 自身の概念の圧縮：新しい語は「規約」と、チェックの ID（C1〜C11）、論点の ID（T1〜T5）だけ。「規約」は持ち主の言葉に合わせた。

## 4. どう検証するか

3回使ったら、差し戻したチェックのうち、チームがそのまま直した数と、チームが当たらないと退けた数、推奨のまま進めた論点の数を見て、見直す（この値と時期は、持ち主が OK、2026-11-14）。

本文の読み手のテストの結果（1回目、2026-11-14、規約と仕様を対象にしていた版）：書いた SKILL.md だけを、流れを知らない別のエージェントに読ませた。架空の図書館のアプリのリポジトリで、CLAUDE.md の下書きと、既存の処理に手を入れる仕様の下書きを、それぞれ見直させた。

次は、意図どおりに答えた。

- 種類の決め方（規約か仕様か）
- 当てるチェックの選び方
- 決めごとが無い論点を推奨付きで聞き、推奨のまま進めたと分けること
- 差し戻しの表の形
- 仕様で C3（判定できない完了の条件）と C7（変えてはいけないものの節が無い）を差し戻すこと

迷った所として挙がった8つのうち、7つを直した。

| 迷った所 | 直したこと |
| --- | --- |
| 見直しなのに、手順1の3が決めごとを書かせる。規約の文書が対象の文書しか無いとき、置き場が分からない | 見直すときは書かずに、置き場と中身を返答に入れる。規約の文書が対象の文書しか無いなら、対象の文書に節を設ける |
| 実在しないパスを、どのチェックで差し戻すか分からない。T5 をどのチェックも使っていない | 手順2で見つけたものは、差し戻しの表に「手順2」として行を足す。T5 は C1（設定ファイルの書き写し）の判定に使う |
| T1 の「切り上げ」の位 | 10 行単位にした |
