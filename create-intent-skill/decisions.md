# create-intent-skill の決定の記録

create-intent-skill を、create-intent-skill 自身の手順で作ったときの記録（2026-11-11）。最初は agent-taxonomy のリポジトリに置いていた。同じ日に、正本をこのリポジトリに移した（中身だけで、履歴は持ち込んでいない）。理由は [policy.md](policy.md) の項目番号（P1〜P6）で書く。要旨は、そのルールが create-intent-skill で何を決めるかを、こちらの言葉で書いたもので、原文の訳ではない。

## 0. 要求を疑った結果（P3 の1段目）

新しいスキルが要るかを先に確かめた。/principles の「Writing a skill」が決めるのは、ルールの置き場所だけ。skill-creator などの既存のスキルは、1つの意図からスキルを書くことはできるが、いくつもの参照先からルールを選んで捨てる手順を持たない。足りないのは「方針を先に決め、参照先のルールをその方針で選ぶ」部分だけなので、create-intent-skill はそこだけを持ち、置き場所の判断は /principles に任せる。

## 3. 形（/principles の判断の手順を上から当てた結果）

1. 機械で判定できるもの：decisions.md の各行に出典の commit があるか、SKILL.md が参照するファイルが実在するか。今は作らない（P3、P4）。手で検査し（PS7）、同じ抜けが2回起きたらスクリプトにする。
2. 分岐の条件（要求を疑って止まる、譲る順で決める）は、SKILL.md の本文に置いた。
3. 毎回要る事実は無い。常に読み込まれるメモリには何も追加しない。
4. 6つの手順はどれも毎回使うので、本文に置いた。手元の道具（プロジェクトの知識カード、作業の記録の計測）がある環境だけで使う手順は、local.md に出した。local.md はこのリポジトリには入れない。使う人が各自で置く任意のファイルにする（README）。
5. 共有するもの：/principles の判断の手順は、サイトの1か所にある。SKILL.md からはリンクで指す。
6. サブエージェントは使わない。
7. 適用されたかは、出力の decisions.md に、採ったルールの ID と理由を書かせることで見える。

起動のされ方：手動でだけ（`disable-model-invocation: true`、WFA8）。

P3 の4段目（回す速さを上げる）：SKILL.md に専用の指示は置かない（P2、P4）。速さは、方針を質問ではなく下書きで確かめること（SC1）と、参照先を HTML ではなく `.md` で読むこと（手順2）から得る。

## 4. どう検証するか

create-intent-skill で作ったスキルを使った作業で、プルリクエストの手戻りのコミットとレビューの往復の回数を、使う前の同じ種類の作業と比べる。create-intent-skill 自体は、作ったスキルの policy.md を人が直した回数を見る。下書きがそのまま OK される回数が増えれば、P5 が役立っている。最初の見直しは、create-intent-skill で3つのスキルを作ったあと（この時期はエージェントの下書き）。その結果は「5. v0 の見直し」に書いた。

## 5. v0 の見直し（2026-11-11）

create-intent-skill で3つのスキル（プルリクエストの説明を書くスキル2つと、数値を含む週次の報告を書くスキル1つ）を作ったあと、持ち主が見直した。P4 に沿って、3回の中で実際に起きたことだけを直した。回数は、記録で確かめられた範囲で書く。
