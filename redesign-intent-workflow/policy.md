redesign-intent-workflow（複数のスキルにまたがる組み立てを設計し直し、移行を create-intent-skill か improve-intent-skill に渡せる大きさの PR に分けるスキル）を設計するときの方針。ルールの採否（[decisions.md](decisions.md)）は、ここの項目番号で理由を書く。

- 決めた人と日付：持ち主（2026-11-13）。
  - 持ち主が決めたもの：
    - 名前（redesign-intent-workflow）と、create-intent-skill・improve-intent-skill の上流に新しいスキルとして足すこと
    - 相談で要った7つの手順（棚卸し、読み手ごとの困りごと、上流で確かめる、案を並べる、推奨付きで聞く、チーム向けの設計書、PR に分ける）。P1〜P7 の材料
    - improve-intent-skill と分ける理由の2つ（入口が違う、improve の縛りが足かせになる）。解決したいことの1つ目と、非目標の1つ目の材料
    - 共有の方針 S1〜S3（[shared-policy.md](../create-intent-skill/shared-policy.md)）
  - 下書きのまま進めたもの（持ち主の確認待ち）：
    - 解決したいことの3つの文
    - P1〜P7 の分け方と言い回し（とくに P6 の「決定の重さを分ける」、P7 の「このスキルでは本文を直さない」）
    - 非目標
    - 譲る順

## 解決したいこと

- 数えた失敗が無くても、複数のスキルにまたがる組み立て（置き場・読み手・信頼の順・スキルの分担）への違和感を、設計の相談として受けられるようにする。根拠：持ち主 2026-11-13（improve と分ける理由の1つ目：入口が違う）。
- 組み立ての変更を、create-intent-skill か improve-intent-skill がそのまま受け取れる大きさの PR に分け、移行の順を決める。根拠：持ち主 2026-11-13（手順7）。
- 人が決めることと、推奨で決めてよいことを分け、人が選ぶだけで設計が進むようにする。根拠：持ち主 2026-11-13（手順5）。

## 方針

- **P1. 先に今の形を棚卸しする。** 置き場ごとに、誰が書き、どのスキルと人が読み、どこまで信じられているかを表にする。表は、読んだ commit の時点の記録として書く。根拠：持ち主 2026-11-13（手順1）。
- **P2. 困りごとを読み手ごとに分け、出典を付ける。** 読み手は人とエージェントに分ける。出典が無いものは「推測」と書く（S1）。根拠：持ち主 2026-11-13（手順2）。
- **P3. 参考の運用は上流の版で確かめる。** 手元の写しで判断しない（S2）。根拠：持ち主 2026-11-13（手順3）。
- **P4. 案ごとに、効果・維持コスト・抜け道を並べる。** 効果は、どの困りごとが消えるかで書く。変えてはいけないものを先に書く。根拠：持ち主 2026-11-13（手順4）。
- **P5. 決めたいことは、推奨付きで選べる形で聞く。** 推奨で決めてよいものは決めて並べる。人が OK した項目と、推奨のまま進めた項目を分けて書く。根拠：持ち主 2026-11-13（手順5）、create-intent-skill/SKILL.md の手順1の4。
- **P6. 設計書はチーム向けに書く。** 根拠には、読み手が確かめられるものを使う（S3）。決定の重さ（戻すのが高くつく決定か、試しに決めたことか）を分けて書く。根拠：持ち主 2026-11-13（手順6）。決定の重さは下書き。
- **P7. 移行は、渡せる大きさの PR に分けて渡す。** 各 PR に、渡し先（create-intent-skill か improve-intent-skill）と前後の依存を付ける。このスキルでは、対象のスキルの本文を直さない。根拠：持ち主 2026-11-13（手順7、improve と分ける理由の2つ目）。「本文を直さない」は下書き。

## 共有の方針

このリポジトリのスキルに共通する方針は、[shared-policy.md](../create-intent-skill/shared-policy.md) にある（S1〜S3）。この方針の上に置き、譲る順の対象にしない。create-intent-skill と一緒に入れる前提なので、相対パスで指す。

## 非目標

- 1つのスキルの、数えた失敗を直すこと。それは improve-intent-skill の仕事。根拠：持ち主 2026-11-13（improve と分ける理由）。
- スキルを1つ新しく作ること。それは create-intent-skill の仕事。下書き。
- 移行の PR を、このスキルの中で実装すること。渡し先のスキルの手順で実装する（P7）。下書き。
- 評価のループ（スキルあり・なしで並べて実行し、採点する仕組み）を組むこと。根拠：create-intent-skill/policy.md の非目標。下書き。
- 参照先の文を訳したり、並べ替えたりして持ち込むこと。根拠：create-intent-skill/policy.md の非目標。

## 譲る順

方針どうしがぶつかったら、上から先に譲る。下書き。

1. 網羅性（対象の範囲の置き場を、一度に全部見直すこと）
2. 参照先への忠実さ（参考の運用の形に合わせること）
3. 移行の速さ（少ない PR で一度に変えること）。渡せる大きさに分ける（P7）
4. 手順の少なさ（このスキル自身の手順を短く保つこと）
5. 意図（解決したいこと）。最後まで譲らない

次の3つは譲る対象にしない（どの場合も守る）：人が決めることを推奨のまま決めない、変えてはいけないものに触る案を推奨しない、作者の文を写さない。
